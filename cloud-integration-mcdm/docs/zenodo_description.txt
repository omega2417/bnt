cimcdm: Reference Implementation and Reproducibility Archive for “Multicriteria Model for Integrating Distributed Systems into Cloud Services”
==============================================================================

Software supplement to: Torstensson, O.; Prokopovych-Tkachenko, D.; Lakhno, V.; Desiatko, A.; Fedotov, S. Multicriteria Model for Integrating Distributed Systems into Cloud Services. Systems, 2026 (submitted manuscript).

Migrating distributed information-processing systems to the cloud is a portfolio decision rather than a sequence of isolated technical upgrades: business value, integration cost, operational risk, reliability, technical readiness and employee acceptance conflict with one another, and their consequences do not materialize at the same rate. This archive is the reference implementation of a three-objective binary portfolio model in which benefit accumulation, organizational adaptation and residual risk are explicit functions of time, together with everything needed to re-derive the article's computational results.

What the software does. It performs exact enumeration of all 262,144 candidate portfolios of the 18-system synthetic benchmark, yielding 83,657 feasible portfolios, 446 Pareto-optimal portfolios and an exact hypervolume of 0.421543. That exact front serves as ground truth against which the heuristics are scored, which separates model validation from algorithm advocacy. The package further implements NSGA-II, a reference-direction (NSGA-III-type) variant and a 231-weight weighted-sum baseline sharing one variation and repair pipeline; the hypervolume, IGD+, spacing and exact-front coverage indicators; paired Wilcoxon signed-rank tests with Pratt zero handling, Holm correction and rank-biserial effect sizes; and a 25-cell sensitivity analysis of the adaptation and economic-benefit accumulation rates, enumerated exactly in every cell.

Reproducibility. A self-verifying validation module re-derives each published number and reports pass or fail per claim, wired into the command-line exit code so it can serve as a continuous-integration gate. All enumeration-driven results reproduce exactly, to the 1e-7 rounding floor imposed by publishing the inputs to six decimals: the feasible count, the front size, the exact hypervolume, the knee portfolio and its derived quantities, every sensitivity corner, and all four weighted-sum indicators. The evolutionary results are stochastic and reproduce in distribution rather than run for run; the README states precisely which comparisons carry over and which do not, including two that do not.

Contents. Python package (src/cimcdm), a Google Colab notebook that runs the entire study in a browser without local installation, a command-line interface, 40 unit and reproduction tests, the article's Appendices A-C as machine-readable CSV, and scripts that regenerate every table and figure.

Scope. The benchmark scenario is synthetic. Reproducing these numbers establishes internal computational correctness for one instance; it does not establish effectiveness in a deployed organization. Decisions are binary, system contributions are additive, and the temporal rates are not empirically calibrated.
