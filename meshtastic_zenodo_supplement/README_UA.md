# Додаток Meshtastic для Zenodo: підготовка експерименту та пошуковий прототип підтримки рішень

Версія 1.1.0 — 28.11.2026. Джерело [59] рукопису logistics-4699826.

## Статус доказів — прочитайте спершу

**Експерименту не проводили, виміряних даних в архіві немає.**

- Стенд із трьох вузлів, описаний у `docs/`, **не збирали, не вмикали й не випробовували**. Протокол є планом.
- Усі 3600 навчальних записів **синтетичні**: їх згенеровано з припущених розподілів, а мітки створює вигадана логістична формула (`mesh_decision/demo.py`).
- Тому нейромережевий прототип **не має виміряної прогностичної точності**. Оцінки на синтетичній відкладеній вибірці (`models/evaluation.json`) — це перевірка самоузгодженості програми: вони показують, наскільки мережа відтворює вигадану формулу. Звичайна логістична регресія відтворює її трохи краще.
- Прототип **не дав жодного результату статті**. Числа статті — модельні прогнози ex ante, обчислені окремими скриптами (`model.py`, `figures.py`), яких у цьому архіві немає.
- Прототип включено лише тому, що він фіксує вхідні поля, які журнал подій має реєструвати під час запланованого польового експерименту (`docs/COLLECTOR_FIELD_MAPPING.md`).

### Виправлення версії 1.0.0

Версія 1.0.0 (https://doi.org/10.5281/zenodo.23798128) містила файл `reference_materials/Meshtastic_Three_Node_Blackout_Experiment_UA.pdf`, у якому було написано, що натурний експеримент «було проведено» на трьох фізичних вузлах Heltec, зокрема під час відключень електроенергії. **Це твердження не відповідало дійсності:** експерименту не було, текст був чернеткою, написаною так, ніби запланований дослід уже відбувся. Англомовний протокол так само згадував «початкове встановлення та випробування з відключенням живлення». У версії 1.1.0 файл вилучено, протокол виправлено. Версію 1.0.0 неможливо видалити із Zenodo; нею не слід користуватися і на неї не слід посилатися.

Також вилучено застарілу копію рукопису з попередньою назвою, а автором запису вказано особу, названу в посиланні [59] статті.

## Запуск

```bash
python -m pip install -r requirements.txt
python -m mesh_decision predict --data data/inference_examples.csv --model models/neural_model.npz --output my_decisions.csv
python run_demo.py --output demo_run_1      # повний цикл: генерація, навчання, рекомендації
```

Кожен рядок результату має стовпець `evidence_status`, який повторює, що модель є синтетичною демонстрацією. Програма відмовляється застосовувати синтетичну модель до рядків із позначкою `measured`.

## Значення рекомендацій

| Код | Значення |
|---|---|
| `INPUT_REVIEW` | Доповнити або виправити вхідні дані |
| `EXPIRED` | Строк задачі минув; не виконувати як актуальну команду |
| `RESTORE_DISPATCH` | Відновити доступність термінала диспетчера |
| `RESTORE_STATION` | Відновити стаціонарний радіовузол |
| `RESTORE_POWER` | Перевірити та відновити необхідне живлення |
| `REFRESH_DATA` | Оновити застарілі спостереження |
| `MODEL_NOT_VALIDATED` | Демонстраційна модель непридатна для фактичних даних |
| `OUT_OF_DISTRIBUTION` | Ознаки виходять за діапазони навчальної вибірки |
| `MANUAL_REVIEW` | Оцінка близька до межі; потрібен розгляд оператора |
| `CHECK_LINK_OR_ALTERNATIVE` | Перевірити покриття, чергу й альтернативний спосіб зв'язку |
| `CONTINUE_WITH_MONITORING` | Продовжувати під наглядом після підтвердження оператором |

Усі пороги — запропоновані налаштування, не перевірені на реальних даних. Програма працює локально, не надсилає команд на радіовузли й не змінює маршрутів. Розміщення нової версії в Zenodo описано в `docs/ZENODO_UPLOAD_UA.md`; DOI версії 1.1.0 присвоює Zenodo під час депонування, тут його навмисно не вказано.
