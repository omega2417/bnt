# AAE-Desk

Програмна система підзвітної агентної підготовки доказів для управлінських рішень
у сфері національної кіберстійкості. Призначена для органів публічної влади:
аналітичних підрозділів, підзвітних посадових осіб, міжвідомчих координаторів
і підрозділів внутрішнього аудиту.

Система реалізує модель **Accountable Agentic Evidence (AAE)** з публікації
O. Torstensson, I. Antypenko, D. Prokopovych-Tkachenko «AI Agents in National Cyber
Resilience Governance: Metadata Discovery and Decision Accountability».
Повний опис проєкту: [`docs/AAE-Desk_Програмний_проєкт.docx`](docs/AAE-Desk_Програмний_проєкт.docx).

## Що робить система

| Елемент моделі | Реалізація |
|---|---|
| Функції F1–F4 (пошук, походження, оцінювання, довідка) | `aae/agents.py`: агенти працюють лише з метаданими |
| Контрольні точки G1–G3 (повний текст, рішення, перегляд) | `aae/workflow.py`: виконують лише люди, з обов'язковими причинами |
| Журнал рішень | `aae/record.py`: лише дописування, геш-ланцюг, зворотне простеження |
| Розподіл ролей (RACI), «агент ніколи не підзвітний» | `aae/roles.py`: перевірка повноважень перед кожною дією |
| Градуйована автономія Z1–Z4, тригери ескалації | `aae/autonomy.py` |
| Показники оцінювання | `aae/indicators.py` |
| Кодування семи рамкових документів (табл. 4) | `aae/frameworks.py` |
| Міжвідомча передача перевірених доказів | пакети з гешем: `Case.transfer`, `Case.import_evidence` |

## Запуск

Потрібен лише Python 3.10 або новіший. Зовнішніх залежностей немає.

```bash
cd aae-desk
python -m aae demo --data ./data          # два демонстраційні сценарії
python -m aae serve --data ./data         # вебінтерфейс: http://127.0.0.1:8000
python -m aae verify --data ./data        # цілісність усіх журналів
python -m aae trace --data ./data 2       # від рішення у справі № 2 назад до запиту
python -m aae brief --data ./data 1       # довідка у форматі Markdown
python -m aae indicators --data ./data    # показники (JSON)
python -m aae frameworks                  # матриця кодування рамкових документів
python -m aae matrix                      # матриця зон автономії
python -m pytest                          # 30 автоматичних тестів
```

У вебінтерфейсі роль обирають угорі сторінки. Дію, на яку роль не має
повноважень, система відхиляє з поясненням.

## Демонстраційні сценарії

1. **Навчання керівництва з кіберризиків** (зона Z2). Агенти знаходять джерела,
   перевіряють походження й пропонують вісім тверджень. Аналітик на G1 шість
   приймає, одне уточнює і одне відхиляє як непідтверджене текстом.
2. **Спосіб імплементації вимог NIS2** (зона Z3 з ескалацією до Z4). Джерело без
   сталого ідентифікатора автоматично піднімає зону. Оцінювання й довідку веде
   аналітик, другий рецензент фіксує окрему думку до рішення. Справа повторно
   використовує два твердження, перевірені в першій справі.

Імена осіб та орган у сценаріях вигадані. Запис каталогу з позначкою
`synthetic` також вигаданий і потрібен, щоб показати нерозв'язане джерело.

## Обмеження прототипу

- Агенти є детермінованими компонентами на правилах, а не мовною моделлю.
  Твердження-кандидати беруться зі сценарного файла
  `aae/data/candidate_statements.json`. Інтерфейси агентів дозволяють підключити
  мовну модель без зміни контрольних точок і журналу.
- Пошук і перевірка походження працюють із локальним знімком метаданих
  (`aae/data/catalog.json`), а не з живими реєстрами (Crossref, EUR-Lex, NIST CSRC).
- Автентифікації немає: роль та ім'я вказує користувач. Для реального
  використання потрібні автентифікація посадових осіб, TLS і захист від CSRF.
- Геш-ланцюг виявляє зміну чи вилучення записів, але не заважає повністю
  переписати файл тому, хто має до нього доступ. Для цього потрібне зовнішнє
  засвідчення гешів (наприклад, кваліфікована позначка часу).
- Робота з інформацією з обмеженим доступом не реалізована: відповідний тригер
  лише піднімає зону автономії.
- Показники в демонстрації ілюстративні й не є емпіричним підтвердженням
  пропозицій P1–P6 з публікації.
