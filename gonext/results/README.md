# Results of the GoNext reproducibility package

Everything in this directory and in `../figures/` is generated by

    bash scripts/reproduce.sh        # from the repository root

which runs `gofmt -l bench`, `go vet ./bench/...`, the equivalence tests
(`go test ./bench/...`), the benchmarks and Experiment 4
(`scripts/run_benchmarks.sh`), and then the analysis and plotting scripts.
Benchmark numbers depend on the machine; see `raw/environment.txt`.

## Raw data (`raw/`)

| File | Content |
|---|---|
| `raw/environment.txt` | Date, `go version`, `GOOS GOARCH`, CPU model, number of CPUs, memory, kernel and the exact benchmark command (Table 2). |
| `raw/bench.txt` | Unmodified output of `GOMAXPROCS=2 go test -p 1 -run='^$' -bench=. -benchmem -count=10 ./bench/...` (Experiments 1–3). |
| `raw/pointervis.csv` | Experiment 4, one row per trial: `mode,trial,finalized,nodes` (10 trials × 3 storage modes × 10,000 nodes, 5 forced GC cycles). |

## Derived results

| File | Produced by | Content |
|---|---|---|
| `platform_group_scores.csv` | `scripts/platform_ranking.py` | Normalized group scores (Equation 1), equal-weight aggregate score (Equation 2), rank, and the shares of first place and top-two among 100,000 Dir(1,…,1) weight vectors (seed 2026) — Figure 2. |
| `platform_ranking.json` | `scripts/platform_ranking.py` | Same data plus method parameters and the leave-one-group-out rankings. |
| `bench_summary.csv` | `scripts/analyze_bench.py` | Median, 25th/75th percentiles (numpy linear method), min, max and number of runs for every benchmark and every reported metric (`ns/op`, `ns/value`, `B/op`, `allocs/op`, `B/value-slice`, `B/value-heap`, `allocs/value`). |
| `table6.csv`, `table6.md` | `scripts/analyze_bench.py` | Table 6: generated-code measurements, median [IQR] of ten runs. Construction allocations and memory come from `BenchmarkMemory` (heap bytes and mallocs per value measured with `runtime.MemStats`; slice bytes = `unsafe.Sizeof` of the element). |
| `table7.csv`, `table7.md` | `scripts/analyze_bench.py` | Table 7: nodes reclaimed while still referenced by live enum values, median and range over ten trials per storage mode. |

## Figures (`../figures/`)

| File | Produced by | Content |
|---|---|---|

## Benchmark ↔ table mapping

| Benchmark | Table 6 row |
|---|---|
| `enumrepr` `BenchmarkConstruct/{R1_interface,R2_flat,R3_compact}` (`ns/value`) | Enum construction, R1–R3 |
| `enumrepr` `BenchmarkMemory/*` (`B/value-slice`, `B/value-heap`, `allocs/value`) | Allocations / Memory columns of the construction rows |
| `enumrepr` `BenchmarkMatch/*` (`ns/value`) | Exhaustive match, R1–R3 |
| `namedargs` `BenchmarkNamedArgs/{GoNext_positional,Config_struct,Functional_options}` | Named/default call rows |
| `genericmethod` `BenchmarkMap/{GoNext_generic_method,Handwritten_loop}` | Generic method + lambda / hand-written loop |
| `genericmethod` `BenchmarkSum/{GoNext_extension_method,Handwritten_sum}` | Extension method sum / hand-written sum |
