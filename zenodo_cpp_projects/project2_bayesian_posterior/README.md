# Проєкт 2. Байєсівський posterior і MAP/HPD-оцінювання (Розділ 3.4)

**Bayesian Spatial Posterior with MAP / HPD / Zonal Mass**

Референсна реалізація підрозділу **3.4** (з факторизованою правдоподібністю
модальностей §3.4.2 та FTM-likelihood §3.5.6). Програма мовою **C++17** без
зовнішніх залежностей, орієнтована на **OnlineGDB** і будь-який `g++`/`clang++`
(>= C++17) чи MSVC.

---

## 1. Що реалізовано

Увесь інференс виконується в **log-domain** (§3.4.3) з `log-sum-exp` нормуванням:

```
predict     p(x | z_{1:t−1})            прогнозний prior (дифузія + relocation)   (eq. 3.6)
likelihood  L(x) = Π_s L_s(x)^{w_s}     факторизація модальностей                (eq. 3.7)
update      p(x|z_{1:t}) = predict·L/Z   нормування, log-sum-exp                  (eq. 3.8–3.9)
```

Модальності:

- **RSSI-блоки** — робастна (Huber) лог-правдоподібність відносно path-loss
  радіокарти; вага `w_s` надходить із Розділу 3.3;
- **FTM/RTT-якорі** — LOS/NLOS-mixture з маргіналізацією bias (§3.5.6);
- **маски доступності** роблять відсутню модальність нейтральним множником `1`
  (відсутність доказу ≠ невизначений вимір).

Просторові виходи (§3.4.6–3.4.11):

| Вихід | Підрозділ | Формула |
|---|---|---|
| MAP-оцінка | §3.4.6 | eq. 3.11 |
| апостеріорне середнє + дисперсія (uncertainty budget) | §3.4.11 | — |
| локальні моди з масою компонент | §3.4.6 | — |
| HPD-область рівня α (може бути незв'язною) | §3.4.7 | eq. 3.12 |
| зональна апостеріорна маса | §3.4.8 | eq. 3.13 |
| стан out-of-map | §3.4.9 | eq. 3.14 |
| ентропія та model evidence (OOD-діагностика) | §3.4.3 | eq. 3.8 |

Критичність зони **не** входить до правдоподібності чи prior (decision-layer
only) — це запобігає circular reasoning (§3.4.8).

## 2. Демонстраційна сцена — «fingerprint twins» (§3.4.10, рис. 3.5)

Пасивні сенсори розташовані **колінеарно** вздовж осі коридору `x = 15`, тому
чистий RSSI-fingerprint **не може** розрізнити джерело праворуч від осі
(серверна, істинне `x=22`) від його дзеркального двійника ліворуч (публічна
зона, `x=8`): обидва рівновіддалені від усіх сенсорів.

- **Case A — PASSIVE-ONLY (RSSI):** posterior **бімодальний**; апостеріорне
  середнє лежить у коридорі **між** модами (демонструє §3.4.6 — чому середнє
  оманливе). Зональна маса ≈ 0,48 / 0,49 між публічною зоною та серверною.
- **Case B — HYBRID (RSSI × FTM):** один FTM-якір біля серверної руйнує
  двозначність. Спільний posterior — це **нормований добуток**, а не середнє
  двох MAP: непідтримувана мода **втрачає масу, але не видаляється безумовно**
  (§3.4.10). Зональна маса серверної → 1,000.

Для наочності на OnlineGDB виводиться ASCII-heatmap posterior (без графічних
бібліотек).

## 3. Property-based інваріанти (§3.4.12)

Програма перевіряє на демо-сцені:

- повна маса (in-map + out-of-map) = 1;
- вилучення FTM-фактора змінює posterior (а маскований — ні);
- порожній evidence повертає prior.

## 4. Як запустити на OnlineGDB

1. Відкрийте <https://www.onlinegdb.com>, мова **C++**.
2. Вставте `src/main.cpp`, натисніть **Run** (введення не потрібне).

```bash
make run

g++ -std=c++17 -O2 src/main.cpp -o bayesian_posterior && ./bayesian_posterior
```

## 7. Наукові застереження

Робочі точки (HPD-рівні, out-of-map пороги, температура калібрування, дисперсії
likelihood) мають статус **to_be_validated**. Калібрований posterior не є
гарантією фізичної істинності за спільного bias усіх модальностей; емпіричне
покриття (coverage), adversarial-, leave-one-domain-out- та out-of-map-сценарії
належать Розділу 4. Усі рисунки/числа тут — ілюстрація структури алгоритму.
