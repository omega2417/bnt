# Проєкт 1. Адаптивне зважування сенсорів (Розділ 3.3)

**Adaptive Sensor Weighting for Tactical Spatial Attribution**

Референсна реалізація підрозділу **3.3** дисертації — декомпонований, аудитований
метрологічний шар адаптивної ваги сенсорного блока в інцидентному вікні.
Програма мовою **C++17** без зовнішніх залежностей, орієнтована на запуск в
онлайн-компіляторі **OnlineGDB** та в будь-якому `g++`/`clang++` (>= C++17) чи MSVC.

---

## 1. Що реалізовано

Формула ваги (3.1) у добутковій (консервативній) формі:

```
w~_s      = m_s · π_s · γ_s · κ_s · ρ_s            (нб. внесок, eq. 3.1)
w_s^base  = w~_s / Σ_j w~_j                         (нормована вага, eq. 3.1)
```

з подальшою проєкцією на множину допустимих політикою значень (задача 3.5):
доменні caps, rate limiter та гістерезис (§3.3.7–3.3.8), аварійне виключення.

Чотири канонічні компоненти якості:

| Компонента | Підрозділ | Зміст | Обчислення в коді |
|---|---|---|---|
| `π_s` provenance | §3.3.2 | верхня межа довіри до походження | геометричне середнє підкомпонентів із нижньою межею |
| `γ_s` geometry | §3.3.3 | очікуваний приріст просторової інформації | приріст `log det` регуляризованої 2-D інформаційної матриці (eq. 3.2) |
| `κ_s` calibration | §3.3.4 | метрологічна чинність | `1{compat} · exp(−age/τ) · (1−uncert)` (eq. 3.3) |
| `ρ_s` completeness | §3.3.5 | повнота, свіжість, ефективний обсяг | геометричне середнє (eq. 3.4) |

Додатково відтворено (згідно з §3.3.6–3.3.11):

- **Маска `m_s`** відрізняє відсутність вимірювання від низької довіри.
- **Reason code** для кожного сенсора — домінантна причина зниження ваги.
- **Weight trace** усіх некомутативних стадій: `base → domain-capped → rate-limited → final`.
- **Trust domains** та обмеження групового домінування (§3.3.7): копія потоку
  в одному домені **не** збільшує сумарну вагу домену.
- **Effective number of independent domains** (inverse Simpson index).
- **Аварійне виключення** (§3.3.8) обходить rate limiter лише за підписаної причини.
- **Критерії завершеності** (§3.3.10): сума активних ваг = 1; нульові ваги для
  неактивних блоків; наявність reason code для кожної ваги.

Підсистема повертає **лише вектор ваг** та діагностику; вона не визначає координату
(це Розділ 3.4) і не класифікує загрозу (Розділ 3.7).

## 2. Демонстраційна сцена

Вбудована сцена (аналітична ілюстрація, **не** емпіричні дані) містить 6 сенсорів:

- `D1`, `D2` — в **одному** trust domain і майже колінеарні → слабка гранична
  геометрія + обмеження доменним cap;
- `D3` — незалежний домен, добра геометрія, але **прострочене калібрування**;
- `D4` — низька provenance (невідомий агент/прострочений ключ) → low-trust;
- `D5` — **аварійне виключення** (revoked certificate): маска → 0;
- `D6` — неактивна маска (сканувався інший канал): нейтральна відсутність.

Ваги обчислюються для двох рівнів дії — `OBSERVE` (доменний cap 0,55) і `AUTO`
(cap 0,40, потрібне незалежне підтвердження) — на **однакових** даних.

## 3. Як запустити на OnlineGDB

1. Відкрийте <https://www.onlinegdb.com>.
2. Виберіть мову **C++** (компілятор підтримує C++17).
3. Скопіюйте вміст `src/main.cpp` у редактор.
4. Натисніть **Run**. Введення не потрібне — сцена вбудована.

## 4. Локальна збірка

```bash
make run
# або напряму:
g++ -std=c++17 -O2 src/main.cpp -o adaptive_weighting && ./adaptive_weighting
```

## 6. Наукові застереження

Конкретні числові робочі точки (caps, `τ`, пороги гістерезису, `rate_delta`) мають
статус **to_be_validated** і повинні визначатися на training/validation-поділах та
підтверджуватися в розділі експериментальної валідації (Розділ 4). Науковим
результатом є сама декомпонована й контрольована конструкція ваги, а не конкретні
коефіцієнти.
